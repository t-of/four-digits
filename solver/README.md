# 最小記号数の計算（four-digits の solver）

2026-11-06 に `~/research/4桁の数字パズル/` で始め、計算が終わったのでここへ移した（元の git の履歴は `~/research/_trash/` 側に残る）。

## 問い
0000〜9999 の各 4 桁と目標 1〜100 について、仕様（[SPEC.md](SPEC.md)）の記号で目標を作るときの **記号の個数の最小値** はいくつか。
T.OF... のゲーム（`~/GitHub/tof/apps/four-digits/`、App Store 予定）の星 3 の基準に使う。2026-11-06 開始。

## ファイル
- `SPEC.md` — 式の仕様（ゲームと共通）と出力の形
- `notes_rules_original.md` — オーナーが 2027 で調べたルールと結果（下敷き。既知の値: 2027 は 1 個 1・2 個 24・3 個 59・4 個 16、47 = 20+27）
- `src/` — 最小記号数の探索
- `results/` — 計算の出力（git に入れない）。`min.bin` はゲームの `../data/min.bin` に写して入れる

## 再現手順
### ビルドと実行
```sh
clang++ -O2 -std=c++17 -o src/minsym src/minsym.cpp
./src/minsym one 2027                  # 1 組を解く（s t m 式 の 100 行。時間は標準エラー）
W=8 nohup src/run_all.sh > results/parts_run.log 2>&1 &   # 全 1 万組を 8 並列
cat results/parts/progress.txt         # 進捗（30 秒ごと）
python3 src/merge.py                   # results/min.bin と results/examples.tsv.gz を作る（run_all.sh が最後に自動で呼ぶ）
python3 src/check.py results/examples.tsv.gz 5000   # 例の式を別の解析器で読み直す（ランダム 5000 問）
```
### 記号を絞った版（難しさの物差し用。OPSET）
環境変数 `OPSET` で使える記号を絞る。未設定（または `all`）は全記号で、結果は上と同じ。
- `OPSET=basic` — 連結・＋ − × ÷・括弧だけ（小数点・単独のマイナス・^・√・階乗・部分階乗なし）
- `OPSET=mid` — basic ＋ 小数点・単独のマイナス・^・√・階乗（N=1 の `!` だけ。N 重階乗と部分階乗なし）
- 見つからない問題は 255（basic は多い）。どの問題も 全記号 ≤ mid ≤ basic になる。
```sh
OPSET=mid W=8 src/run_all.sh          # 出力は results/mid/parts/、まとめは results/mid/min_mid.bin と results/mid/examples_mid.tsv.gz
OPSET=basic W=8 src/run_all.sh        # results/basic/ に同じ形（min_basic.bin, examples_basic.tsv.gz）
OPSET=mid ./src/minsym one 2027
OPSET=mid python3 src/merge.py        # merge.py も OPSET を読む
```
進捗は `results/<OPSET>/parts/progress.txt`。全記号版（未設定）は今までどおり `results/parts/`・`results/min.bin`・`results/examples.tsv.gz`。

- 途中で止まったら同じ `W` で `run_all.sh` を流し直す（`results/parts/part_<w>.tsv` の `#done s` の組を飛ばして続きから）。`W` を変えると組の割り振りがずれるので変えない。
- 環境変数で範囲を変えられる: `FACT_MAX`、`CMAX`、`LEVEL_CAP`（下の表）。部分階乗は冪乗の底にできない（SPEC。2026-11-06 オーナーが決めた）。`SUBF_BASE=1` で旧仕様（底にできる）。

### 探索の範囲（この中での最小）
| 項目 | 値 |
|---|---|
| 値 | 正確な有理数。|分子| ≤ 10³⁶、分母 ≤ 10¹⁸。途中の掛け算・足し算が __int128 で溢れる組み合わせは捨てる |
| N 重階乗（N=1 の階乗も） | 対象 n は 0〜1000 の整数、N は 1〜n−2（N ≥ n−1 は n と同じなので作らない）。0!=1!=1。積が上の上限を超えるものは捨てる |
| 部分階乗 | 対象 n は 0 以上の整数で、!n が上限以下のもの（n ≤ 32） |
| 冪乗 | 指数は整数。底が 0・±1 なら指数の大きさは制限なし（0 の 0 以下乗は不可）。それ以外は値の上限で自然に切れる（|指数| ≤ 130 で打ち切り） |
| √ | 分子・分母がともに平方数のときだけ |
| 単項演算を重ねる回数 | 制限なし（記号数の上限の中で） |
| 記号数の上限 | 30（`CMAX`）。ここまでで見つからなければ 255 |
| 1 区間の項目数の上限 | 6000 万（`LEVEL_CAP`、メモリ保護。超えた組は `#overflow` と記録） |

### 方法
数字の区間 [i,j) ごとに、記号数 c ちょうどで作れる（値, 種類）を c の小さい順に作る（`src/minsym.cpp` の先頭のコメント）。
種類は括弧の要否を決める最上位の演算の高さで、使える場所の広さで 7 つ（足し引き・左端が単独のマイナスの足し引き・単独のマイナス／左端がそれの掛け割り・掛け割り・冪乗・階乗/√/部分階乗・数/括弧）。
同じ値で使える場所が広い種類が同じ記号数以下で既にあれば捨てる。全体の区間で 1〜100 がそろった記号数で止める。
`a+(b−c)` は `a+b−c`、`a×(b÷c)` は `a×b÷c` と書いても値も記号数も同じなので、+ と × の右側の同じ高さには括弧を付けない。

### 検算
- 2027（今の仕様）で元の結果（1 個 1・2 個 24・3 個 59・4 個 16、4 個の 16 数）と完全に一致。旧仕様（`SUBF_BASE=1`、部分階乗を冪乗の底にできる）だと 20 = `20×!2^7`、21 = `20+!2^7` が 3 個になり、1 個 1・2 個 24・3 個 61・4 個 14。
- `src/check.py`（探索とは別に書いた SPEC の文法の解析器）で、例の式の値・数字の順番・記号数を確かめる。
